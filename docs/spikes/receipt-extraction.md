## Recommendation

tesseract.js **passes the bar** (17/20 all-four-fields correct).

### Use tesseract.js for the initial build

- Runs entirely on-device — no network, no credentials, consistent with the offline-first PWA architecture.
- Average OCR time of 274 ms per receipt is acceptable for a user-triggered feed action.
- The simple line-based parser handles standard receipt layouts. Delivery-app order-confirmation style receipts may need a small layout-aware parser variant.
- Keep Amazon Textract AnalyzeExpense as the fallback for low-confidence extractions (below `minExtractionConfidence: 0.8`). It is already in `approved_packages.after_spike` in `docs/speed.yml`.

### What to watch

- **Re-photographed duplicates** (R005): OCR accuracy is sufficient for duplicate detection via receipt ID + total + merchant fingerprint, even with rotation and blur.
- **No-time receipts** (R009): correctly extract date but no time — these go to review per the meal rules, as expected.
- **Non-food merchants** (R008): OCR works fine; food-category rejection is a separate domain-logic step, not an extraction concern.
- **Future receipts** (R007): OCR works fine; future-date rejection is domain logic.

### Next steps

1. Add `tesseract.js` to the main project: it is already in `approved_packages.after_spike`.
2. Promote the parser functions from this spike to `src/domain/meals/extract.ts`, wrapped in Zod output schemas.
3. Set `minExtractionConfidence` threshold using Tesseract's word-confidence scores (available in `data.words`).
4. The 20 synthetic PNGs in `spikes/receipts/output/` become the golden set for regression tests (speed.yml C9).
