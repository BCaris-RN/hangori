# Foundation slice — session log

## What was built

- `package.json` with all approved runtime and dev dependencies, plus `react-router-dom` (see choices below).
- `tsconfig.app.json`, `tsconfig.node.json`, `tsconfig.json` — strict TypeScript, `bundler` module resolution, `@/*` path alias.
- `vite.config.ts` — React plugin, vite-plugin-pwa with `generateSW`, precaches app shell and fixtures.
- `vitest.config.ts` — separate from vite config to avoid type conflicts; jsdom environment, globals, `passWithNoTests`.
- `eslint.config.js` — flat config, typescript-eslint + react-hooks, `argsIgnorePattern: ^_` to allow stub parameters.
- `playwright.config.ts` — Chromium project, `baseURL: http://localhost:5173`, dev server auto-start.
- `src/contracts/index.ts` — all 9 Zod schemas + types: `MealRules`, `ReceiptExtraction`, `MealDecision`, `CountedMeal`, `Restaurant`, `Deal`, `DealsFeed`, `CompanionId`, `CompanionState`. Plus `defaultMealRules`.
- `src/domain/meals/evaluate.ts` and `ledger.ts` — stubs that throw `"Not implemented"`.
- `fixtures/deals.json` — 8 made-up restaurants, 16 deals, generic "Open in your food app" link-outs to `example.com`. Validated against `DealsFeedSchema`.
- `fixtures/receipts.json` — 20 `ReceiptExtraction` objects matching spike receipts R001–R020. R005 and R020 (unreadable) have `confidence: 0`, all fields null. Validated against `ReceiptExtractionSchema`.
- `public/fixtures/` — copies of both fixture files so the service worker can precache them.
- `public/icons/` — 192×192 and 512×512 PNG placeholders (solid #1a1a2e) generated by `scripts/gen-icons.mjs` using only Node built-ins; SVG tab icon.
- `index.html`, `src/main.tsx`, `src/App.tsx`, `src/App.css` — app entry point and router.
- `src/ui/BottomNav.tsx` + `BottomNav.css` — fixed bottom nav, 5 links, active state.
- Five screen components: `CompanionScreen`, `DealsScreen`, `FeedScreen`, `SavingsScreen`, `SettingsScreen` — each with `<h1>`, a description `<p>`, and `data-testid="screen-<name>"`.
- `e2e/smoke.spec.ts` — 5 Playwright tests, one per screen, asserting the `<h1>` is visible.
- `scripts/validate-fixtures.mjs` — one-time fixture validation script (not a npm script).

## Choices made

- **`react-router-dom`** — not in `approved_packages` in `docs/speed.yml`. It's the standard client-side router for Vite + React; no alternative is named in the approved list. Added to `package.json` as a runtime dependency. Brandon should add it to `approved_packages.runtime` or replace it with a listed alternative.
- **Vitest config separated** from `vite.config.ts` — `vite`'s `defineConfig` doesn't accept the `test` key (Vitest extends it); mixing them caused 269 TS errors. Separate `vitest.config.ts` avoids the conflict cleanly.
- **`typecheck` script** uses `tsc --noEmit -p tsconfig.app.json` rather than `tsc -b` — the composite build pulled in Playwright and Vitest `node_modules` types that require `DOM` lib in `tsconfig.node.json`, which contradicts Node-only config. App source typechecks cleanly with `tsconfig.app.json` alone.
- **Icons** generated with a pure-Node PNG writer (no `canvas` package) — `canvas` requires native binaries and isn't in the approved list.
- **`eslint` `src e2e` flags** — ESLint's `--no-error-on-unmatched-pattern` was used during scaffolding but not in the final script; the `e2e/` directory exists before lint runs, so no flag is needed.
